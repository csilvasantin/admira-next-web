ADmiraNeXT · MCP · Generador de Presentaciones

Conecta tu asistente al Generador de Presentaciones.

De un cliente y un problema a una presentación viva. Este servidor MCP deja que un consejero de silicio, o cualquier persona con su asistente (Claude, Cursor, OpenCode…), liste, cree, regenere y restaure presentaciones con los mismos permisos que tiene en /usuarios.

1 · Conectar

Endpoint: https://www.admiranext.com/mcp · JSON-RPC 2.0 · Streamable HTTP (responde JSON, o SSE si pides text/event-stream).
Autenticación: Authorization: Bearer anmcp_… — token personal, ligado a tu usuario del directorio.

Configuración para Claude / Cursor / OpenCode

{
  "mcpServers": {
    "admiranext-presentaciones": {
      "url": "https://www.admiranext.com/mcp",
      "headers": { "Authorization": "Bearer anmcp_TU_TOKEN" }
    }
  }
}

Prueba desde la terminal

curl -s https://www.admiranext.com/mcp \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer anmcp_TU_TOKEN" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"help"}}'

2 · Conseguir un token

  1. Tu usuario tiene que existir en /usuarios, activo y con el proyecto generador-de-presentaciones (o *).
  2. Un administrador crea el token: POST /api/mcp-tokens con {"email":"tu@admira.com","label":"mi asistente"} desde su sesión (o desde el panel de usuarios).
  3. El token se muestra una sola vez. Se guarda solo su huella. Revocarlo, o darte de baja, corta el acceso al instante.

Sin token puedes hacer initialize, tools/list y help; nada más.

3 · Tools

ToolQué haceRol mínimo
helpEsta ayuda. tema opcional: crear, presentaciones, versiones, permisos.ninguno
list_presentationsPresentaciones existentes: slug, nombre, web, idiomas, entregables.viewer
list_decksPacks de deck (antes/después) para create_presentation.viewer
get_presentationContenido vivo de una presentación (láminas, idiomas, secuencia). {client}viewer
create_presentationCrea, o regenera con overwrite:true, a partir de displayName, website, problem, audience… Devuelve slug, contraseña y URLs.editor
generation_statusEstado de la generación (idiomas × entregables). {client}viewer
list_versionsHistorial de versiones. {client}viewer
restore_versionRestaura una versión. {client, id}editor
presentation_urlsURLs de la presentación, la sala y el historial. {client}ninguno

4 · Flujo típico de un consejero

  1. list_presentations → ¿ya existe el cliente?
  2. create_presentation con nombre, web oficial (de ahí sale el logo), problema que resolvemos y a quién se presenta. Castellano e inglés siempre; añade idiomas con languages.
  3. generation_status hasta que todos los entregables estén done.
  4. presentation_urls → comparte la URL privada y la contraseña con el cliente. La sala (/presentacion) tiene salida de audiencia sin notas.

5 · Permisos y seguridad

  • El token no lleva privilegios: en cada llamada se cruza con el directorio. admin → todo · editor → crear, regenerar, restaurar · viewer → solo lectura.
  • Cada tool llama a la API que el generador ya tiene, en el mismo origen, con una sesión de 5 minutos emitida a nombre del dueño del token. Todo queda en la auditoría de accesos del generador.
  • El MCP no guarda contraseñas de clientes ni tokens: solo huellas.
